# SentryGlide classifier - development model

## Intended use

This model validates the complete SentryGlide software path: dataset loading, specimen-level
splitting, RGB and geometric feature fusion, ONNX export, temperature calibration, OOD scoring,
and runtime inference. It is not approved for physical or clinical waste routing.

## Training data

- Source: `dataset-sim/`, generated by `bmwvision make-sim-dataset`
- Classes: all 19 keys in `taxonomy.yaml`
- Split boundary: `physical_id` (no specimen occurs in more than one split)
- Image input: 160 x 160 RGB
- Additional input: 10 standardized geometric/depth features

## Results

- Untouched synthetic test frame accuracy: 91.18%
- Accepted-placement errors at `c_hold=1`: 0 in 23 accepted placements
- Dangerous routes: 0 in 34 test placements
- Dangerous-error 95% upper bound: 8.43%
- Required target: 0.10%
- Formal decision verification: **FAIL - insufficient independent test placements**

The safety target needs approximately 3,000 independent evaluation placements with zero
dangerous routes. Synthetic performance must not be presented as real-world accuracy.

## Required before hardware use

1. Capture real specimens from the final camera, lens, lighting, inspection chamber, and sensor.
2. Include at least three physical specimens per class to run the code; substantially more are
   needed for useful generalization.
3. Retrain using `bmwvision train --dataset dataset --out models`.
4. Refit temperature, OOD, and the HOLD policy with `fit-decision`.
5. Run `verify-decision` once on untouched physical specimens.
6. Obtain infection-control approval for `taxonomy.yaml` and the decision cost matrix.
